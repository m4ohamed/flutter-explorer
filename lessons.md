# 📋 Lessons Learned

## 🚀 Native Modules & ABI
- **The Problem**: Electron (VS Code) often uses a different Node.js ABI version than the system Node.js.
- **The Solution**: Use `@electron/rebuild` and target the specific Electron version of VS Code. Always implement a **JSON Fallback**.
- **The Tip**: Add a `rebuild` script to `package.json` (e.g., `"rebuild": "electron-rebuild -v 32.2.6 -f -w better-sqlite3"`) to quickly fix ABI mismatches.
- **How to find the version**: Open VS Code → Help → About. Look for the **Electron** version (e.g., 32.x.x). Use this version in your rebuild command to ensure binary compatibility.

## 🔍 Parsing & Code Analysis
- **Brace Tracking**: Always use "masked" source to prevent strings/comments from breaking scope logic.
- **Multi-line Headers**: Handle class definitions that span multiple lines.
- **Riverpod/Hooks**: Explicitly handle specialized build methods and state classes.

## 🗺️ Navigation & Paths
- **Consistency**: Centralize file opening in a single command to handle Windows/Unix path differences reliably.

## 🧩 MCP Server Organization
- **Modularity**: Domain-specific logic should be in separate classes (`ArbEditor`, `CodeAnalyzer`, `DirectSearch`).
- **Registration Safeguards**: When refactoring or moving tools, always verify that the same tool name isn't registered twice, as this causes a fatal error on startup.
- **Context-Aware Hints**: Add a `_hints` field to MCP tool responses to suggest logical next steps. This guides the AI and reduces manual user prompting.

## 🧠 Advanced Search & Knowledge
- **RRF (Reciprocal Rank Fusion)**: Optimal way to merge BM25 text search with semantic vector search.
- **Query Boosting**: Use naming conventions (PascalCase/snake_case) to heuristically boost relevant code kinds.
- **Community Wiki**: High-level architecture documentation can be auto-generated by analyzing the graph's community structure and execution flows.

## 🧹 Maintenance & Best Practices
- **Unused Imports**: Always double-check and remove unused imports (like `os` in `ProjectDetector`) after refactoring.
- **SQLite Side-Files**: When migrating or moving a SQLite database, never forget the `-wal` and `-shm` side-files. These are critical for data integrity and should be moved or cleaned up together with the main `.db` file.
- **Robust Root Discovery**: Don't rely solely on `process.cwd()`. Implement a detector that looks for VCS markers (`.git`) or project anchors (`pubspec.yaml`) to correctly identify the project root even when started from a subfolder.
- **Centralized Data**: Use a dedicated hidden folder (like `.flutter-explorer/`) in the project root for tools-specific data rather than polluting standard folders like `.vscode/`.
- **AI-Guided Development (Skills)**: Provide structured instructions (skills) in the repository to guide AI agents. This ensures the AI follows established patterns for codebase exploration, debugging, and refactoring without needing constant user guidance.
- **Nested Template Literals**: When generating code that contains markdown with backticks (like skill files), avoid nested template literals if possible. Using `Array.join('\n')` is a safer way to construct multi-line content with special characters in code generators.
